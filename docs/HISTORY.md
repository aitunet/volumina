- **2026-09-05** — S1.6 done and verified: the chapter list on the book screen. Chapters render in order with their running time, each row links to its own editor, and the order is saved the moment it changes — by drag for a mouse, by Up and Down buttons for everyone else, because an ordering tool that needs a mouse is an ordering tool some people cannot use at all. `Support/Duration` formats seconds as `h:mm:ss` or `m:ss` and knows nothing about audiobooks, so it leaves with the rest of `Support/`. - **2026-09-05** — Two faults found in that work before it was committed, both caught by verification rather than by reading. First: `Chapter::for_book()` ordered by the `volumina_order` meta inside `WP_Query`, which joins on that key, so a chapter that had never been given a position had no row to join to and vanished from its own book without a sound. The sort now happens in PHP over the meta cache `WP_Query` has already primed — a book has tens of chapters, so it costs nothing and cannot lose one. Position zero is treated as "not placed yet" and sorts last, where an editor will find it, rather than first pretending to be chapter one. Second: the two failure messages in `admin-chapters.js` were hard-coded English. They now come from `wp_localize_script`, along with a "Moved to position %1$d of %2$d." announcement, so keyboard reordering says where the chapter landed instead of moving it in silence.
- **2026-09-05** — Also fixed while verifying: `save()` cleared the `aria-live` region a fraction of a second after the keyboard move had announced the new position, erasing it before a screen reader could read it. The clear moved into `announce()` itself, which now empties the region and sets the message on the next frame — that keeps the same message audible twice in a row, which was the only thing the clear was ever for.
- **2026-09-05** — `languages/volumina.pot` regenerated with WP-CLI: 109 strings, translator comments carried through on every placeholder.
- **2026-09-05** — S1.7 done and verified: the chapter details box. A chapter picks its book from a select, its audio from a media frame restricted to audio, and its running time fills itself in from the file. The position is shown but not editable, with a link to the book screen — two screens that both set the position would be two sources of truth waiting to disagree, the same reasoning that gave the book one cover instead of two. `Chapter::next_order()` counts from the highest position in use rather than from the number of chapters, so a book whose numbering has gaps cannot hand the same position to two chapters.
- **2026-09-05** — Nine cases proved in a running WordPress, one save each: a forged nonce writes nothing; a logged-out request with a valid nonce writes nothing; audio chosen with the duration left blank reads 2730 seconds out of the file and lands at position 5, the end of its book; a duration corrected by hand survives the next save; an image attachment smuggled into the audio field is rejected on the server by its MIME type, not by the browser; an attachment ID that does not exist is rejected; moving the chapter to another book renumbers it to the end of that one; a book ID that is not a book clears the book and the position together; and saving twice without changing anything leaves the position where it was instead of pushing it along. `debug.log` still absent.
